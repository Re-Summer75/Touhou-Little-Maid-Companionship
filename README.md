> **“朝夕相伴，不止于工作。”**
>
> 这是一个为《车万女仆》(Touhou Little Maid) 深度定制的扩展模组。我们为女仆补上了成长、进度、饥饿与健康的完整闭环，也把二级动作物理、环境风场与渲染修正带进模型表现，让她真正成为你在 Minecraft 世界中不可或缺的伙伴。

## 功能总览

| 模块 | 内容 | 运行侧 |
| --- | --- | --- |
| 成长与等级 | 经验积累、等级提升、界面提示 | 服务端 + 客户端 |
| 原版进度系统 | 每只女仆独立的 advancement 树与专属页签 | 服务端 + 客户端 |
| 饥饿与健康 | 独立饥饿值、饱和度、自动进食、双通道回血 | 服务端 |
| 沉浸式互动 | 面部追踪喂食、状态气泡、请求动作 | 客户端 |
| 骨骼物理 | VRM 弹簧骨二级动作、碰撞代理、接触感知枢轴 | 客户端 |
| 环境风场 | 可复现的空间风场与逐骨受风响应 | 客户端 |
| 渲染修正 | Gecko 模型逐面外法线与绕序重算 | 客户端 |
| 智能行为 | 低耐久工具自动替换等工作保护 | 服务端 |

## 核心特性

### 成长与等级系统

- 女仆在完成日常工作、被投喂、达成进度时积累经验并提升等级。
- 经验来源分类记录，等级信息直接嵌入本体女仆界面，不额外占用操作区。

### 原版进度系统

- **每只女仆拥有真实的 `PlayerAdvancements`**：通过维度级镜像玩家把女仆行为喂进原版触发器，玩家能做的进度女仆基本都能做。
- **完整桥接表**：物品变化、位置、战斗、药水效果、进食、跨维度、钓鱼、坠落、工具损耗、合成、繁殖、放置方块、蜂蜜块下滑等均已接入，实在没有事件的三处才用 mixin。
- **内置进度线**：从初次见面到完美女仆，共 12 条内置进度，奖励直接折算成女仆经验或背包物品。
- **独立进度页**：女仆界面新增页签，可缩放拖动的进度树、图标条与完成度提示。
- **本体进度隔离**：车万女仆本体那套“玩家如何与女仆相处”的进度被整个命名空间排除，避免女仆自己白拿奖励。

### 饥饿值与健康

- **独立饥饿机制**：女仆拥有自己的饥饿值与饱和度，工作、空闲分档消耗，休息与睡眠不消耗，区块卸载后不继续下降。
- **自动进食**：饥饿值不高于阈值时，依次检查手持与背包食物，复用本体 Work Meal 的处理器与黑名单。
- **双通道回血**：基础饥饿值回血保留三档速度，饱和度另有一套独立的快速回血计时器，两者并行不互相重置。
- **拒绝进食**：饱和度满时服务端拒绝所有口部喂食，女仆通过摇头、音效与气泡反馈“吃不下了”。
- **精细互动**：支持直接喂食整块蛋糕，按原版七片合计营养值折算恢复，创造模式不消耗。

### 沉浸式互动

- **面部追踪粒子**：喂食碎屑精确追踪模型面部坐标动态生成，兼容 Gecko、Bedrock 与 YSM 三套几何来源。
- **状态气泡**：饥饿、工具耐久过低、自动换工具等场景弹出专属聊天气泡与短暂请求动作。
- **准星提示**：手持食物、药品或可交互物品时给出对应提示，并处理河童罗盘等例外。

### 骨骼物理（VRM 弹簧骨）

为尾巴、头发、耳朵、裙摆、丝带、披风、翅膀等自由摆动骨骼添加一层二级动作，实现参考 VRM `VRMC_springBone`。

- **刚度拉回动画**：作者姿态始终是弹簧的平衡点，惯性与风只做叠加，不会把静止造型搬走。
- **全自动骨骼识别**：融合模型元数据、名称语义、几何 AABB、分叉拓扑与空间位置综合评分，高置信才驱动；肢体、武器、面部组件与固定头饰保持刚性。
- **力臂归一化**：从几何推导每根骨骼的支点力臂，按末端行程而非角度限制摆幅，长短部件服从同一套规则，零逐骨骼硬编码。
- **接触感知枢轴**：分析网格表面支撑稳定性推断合理旋转中心，修正绑定锚点离谱的第三方模型，同时保守限幅避免把网格搬到作者从未放置的位置。
- **统一碰撞代理**：自动生成 Plane / Sphere / Capsule / Box 与网格碰撞体，配合布料分层规划减少常见穿模。
- **零分配热路径**：最小活动骨架 + 扁平预序迭代 + scratch 复用，逐帧堆分配为 `0 B`，并附带独立性能基准任务。
- **模型物理元数据**：资源包可提供 sidecar 配置显式指定软体链、排除节点与物理参数，覆盖自动结果。
- **调试工具**：`/maidphysicsdebug` 获取骨骼调试棒，可视化骨架分类、碰撞代理与决策链路。

### 环境风场

- 宏观风向、阵风包络与波浪前沿由维度、世界坐标与 `gameTime` 生成，同一阵风成片扫过全场，多人同屏仍处于同一片连续风场。
- 小尺度按实体与骨骼哈希去相关：每个模型、每根骨骼有各自的涡旋相位、幅度调制与气动迟滞，不创建随机对象、不依赖墙钟，重复渲染可复现。
- 风强综合维度基础值、雨量雷暴、相对海平面高度、浸水与开阔度探测；室内与水下仅保留很弱的气流。
- 风是加在弹簧上的侧向偏置并扣除持续分量，只保留阵风，露天站立不会常年斜着一片裙摆。

### 模型渲染修正

- 按实际顶点为每个 cube 独立重算六面外法线与外向绕序，修正 mirror cube 在使用 `gl_FrontFacing` 的光影下明暗错误。
- 修复本体 Sodium 路径 DOWN 法线分量的写入错误，只让确实需要绕序修正的骨骼退出批量快速路径。
- 法线与绕序位掩码按网格身份弱缓存，热路径零堆分配，F3+T 与自定义模型热加载会自动失效。

### 智能行为

- 工作时工具耐久过低会自动从背包寻找备用工具替换，防止附魔工具损坏。

## 依赖与安装

### 环境要求

- **Minecraft**：`1.20.1`
- **Mod Loader**：`Forge 47.4.0` 及以上
- **前置模组**：[Touhou Little Maid](https://github.com/TartaricAcid/TouhouLittleMaid) `>= 1.5.3`（必须）

### 可选兼容

- **Sodium / Embeddium**：已适配其渲染快速路径，法线修正与批量路径共存。
- **光影包**：外法线修正针对使用 `gl_FrontFacing` 的光影场景，阴影阶段不参与面追踪。

### 安装方法

1. 确认已安装对应版本的 Forge 与车万女仆本体。
2. 从 [Releases](https://github.com/Re-Summer75/Touhou-Little-Maid-Companionship/releases) 下载 `tlm-companionship-1.20.1-forge-x.x.x.jar`，放入游戏根目录的 `mods` 文件夹。
3. 启动游戏即可。

> 当前处于 `v0.0.3` 测试阶段，功能可用但仍在快速迭代，建议先备份存档。

### 分支约定

主分支以 Minecraft 版本号命名（当前为 `1.20.1`），后续新版本会开设独立分支，可复用部分通过分支间移植维护。

### 构建与验证

```bash
./gradlew build
./gradlew --offline cleanTest check
```

`check` 会串联骨骼物理、进度域与渲染法线的离线验证；另有 `benchmarkBonePhysics` 报告预热后的每帧耗时、访问节点数与线程分配量。

## 参与贡献

欢迎提交 Bug 报告、兼容性问题、功能建议与 Pull Request。自定义模型在骨骼物理下表现异常时，请附上模型文件与调试棒的转储信息。

### 需要先知道的开发方式

本项目全程使用 AI Agent 辅助开发，**单次提交的改动范围通常较大**，可能同时涉及多个模块的重构、文档同步与验证套件更新。这带来两点影响：

- 主分支推进较快，动手前建议先同步最新代码，避免在已被重构掉的结构上做修改。
- 上游历史里的大颗粒提交不代表本仓库的提交规范。**请你的 PR 采用原子化提交**：一个提交只做一件事，便于评审、定位回归与必要时单独回滚。

### 提交建议

- 一个 PR 聚焦一个问题或一个特性，不要把无关的格式化、重命名混进来。
- 提交信息使用 `type(scope): 描述` 形式，例如 `fix(physics): 修正裙摆碰撞代理半径`。
- 改动涉及物理、进度或渲染法线时，请本地跑过 `./gradlew --offline cleanTest check`。
- 新增机制请同步更新 `docs/` 下对应模块的文档。

### 流程

1. Fork 本仓库，从目标版本分支（当前为 `1.20.1`）切出特性分支。
2. 按原子化粒度完成提交。
3. 推送分支并开启 Pull Request，说明改动动机与验证方式。
