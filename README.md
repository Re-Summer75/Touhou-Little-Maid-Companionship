> **“朝夕相伴，不止于工作。”**
>
> 这是一个为《车万女仆》(Touhou Little Maid) 深度定制的扩展模组。我们为女仆补上了成长、进度、饥饿与健康的完整闭环，也把二级动作物理、环境风场与渲染修正带进模型表现，让她真正成为你在 Minecraft 世界中不可或缺的伙伴。

## 功能总览

| 模块 | 内容 | 运行侧 |
| --- | --- | --- |
| 成长与等级 | 经验积累、等级提升、界面提示 | 服务端 + 客户端 |
| 原版进度系统 | 每只女仆独立的 advancement 树与专属页签 | 服务端 + 客户端 |
| 饥饿与健康 | 独立饥饿值、饱和度、自动进食、双通道回血 | 服务端 |
| 沉浸式互动 | 面部追踪喂食、状态气泡、请求动作 | 客户端 |
| 骨骼物理 | VRM 弹簧骨二级动作、碰撞代理、接触感知枢轴 | 客户端 |
| 环境风场 | 可复现的空间风场与逐骨受风响应 | 客户端 |
| 渲染修正 | Gecko 模型逐面外法线与绕序重算 | 客户端 |
| 原版 AI 优化 | 寻路缓存、移动意图软协调、任务保护 | 服务端 |
| 数据驱动陪伴智能 | Utility、可恢复计划、对象感知、能力、学习与多女仆协调 | 服务端 |

## 核心特性

### 成长与等级系统

- 女仆通过拾取经验球、获得进度奖励或管理员命令积累经验并提升等级。
- 经验来源分类记录，等级信息直接嵌入本体女仆界面，不额外占用操作区。

### 原版进度系统

- **每只女仆拥有真实的 `PlayerAdvancements`**：通过维度级镜像玩家把女仆行为喂进原版触发器，玩家能做的进度女仆基本都能做。
- **完整桥接表**：物品变化、位置、战斗、药水效果、进食、跨维度、钓鱼、坠落、工具损耗、合成、繁殖、放置方块、蜂蜜块下滑等均已接入，实在没有事件的三处才用 mixin。
- **内置进度线**：覆盖喂食、等级、累计经验和好感，共 12 条内置进度，奖励直接折算成女仆经验或背包物品。
- **独立进度页**：女仆界面新增页签，可缩放拖动的进度树、图标条与完成度提示。
- **本体进度隔离**：车万女仆本体那套“玩家如何与女仆相处”的进度被整个命名空间排除，避免女仆自己白拿奖励。

### 饥饿值与健康

- **独立饥饿机制**：女仆拥有自己的饥饿值与饱和度，工作、空闲分档消耗，休息与睡眠不消耗，区块卸载后不继续下降。
- **自动进食**：饥饿值不高于阈值时，依次检查手持与背包食物；本地无餐时会通过意图 AI 前往 8 格内的 TLM 零食柜，从柜内事务式取出一份。全部来源复用本体 Work Meal 的处理器与黑名单。
- **双通道回血**：基础饥饿值回血保留三档速度，饱和度另有一套独立的快速回血计时器，两者并行不互相重置。
- **拒绝进食**：饱和度满时服务端拒绝所有口部喂食，女仆通过看向主人、挥手、音效与气泡反馈“吃不下了”。
- **精细互动**：支持直接喂食整块蛋糕，按原版七片合计营养值折算恢复，创造模式不消耗。

### 沉浸式互动

- **面部追踪粒子**：喂食碎屑精确追踪模型面部坐标动态生成，兼容 Gecko、Bedrock 与 YSM 三套几何来源。
- **状态气泡**：饥饿、背包已满、工具耐久过低、自动换工具等场景弹出带防刷冷却的专属聊天气泡；需要协助的状态会附带短暂请求动作。
- **准星提示**：手持食物、药品或可交互物品时给出对应提示，并处理河童罗盘等例外。
- **交互按键开关**：`Shift + 右键`开界面、空手右键坐下这套手势可在 `config/tlm_companionship/interaction.toml` 中关闭，关闭后右键交互交还车万女仆本体。

### 骨骼物理（VRM 弹簧骨）

为尾巴、头发、耳朵、裙摆、丝带、披风、翅膀等自由摆动骨骼添加一层二级动作，实现参考 VRM `VRMC_springBone`。

- **刚度拉回动画**：作者姿态始终是弹簧的平衡点，惯性与风只做叠加，不会把静止造型搬走。
- **全自动骨骼识别**：融合模型元数据、名称语义、几何 AABB、分叉拓扑与空间位置综合评分，高置信才驱动；肢体、武器、面部组件与固定头饰保持刚性。
- **力臂归一化**：从几何推导每根骨骼的支点力臂，按末端行程而非角度限制摆幅，长短部件服从同一套规则，零逐骨骼硬编码。
- **接触感知枢轴**：分析网格表面支撑稳定性推断合理旋转中心，修正绑定锚点离谱的第三方模型，同时保守限幅避免把网格搬到作者从未放置的位置。
- **统一碰撞代理**：自动生成 Plane / Sphere / Capsule / Box 与网格碰撞体，配合布料分层规划减少常见穿模。
- **零分配热路径**：最小活动骨架 + 扁平预序迭代 + scratch 复用，逐帧堆分配为 `0 B`，并附带独立性能基准任务。
- **模型物理元数据**：资源包可提供 sidecar 配置显式指定软体链、排除节点与物理参数，覆盖自动结果。
- **玩家开关**：首次启动后可在 `config/tlm_companionship/client.toml` 中设置 `physics.enabled`，关闭客户端骨骼物理。
- **调试工具**：`/maidphysicsdebug` 获取骨骼调试棒，可视化骨架分类、碰撞代理与决策链路。

### 环境风场

- 宏观风向、阵风包络与波浪前沿由维度、世界坐标与 `gameTime` 生成，同一阵风成片扫过全场，多人同屏仍处于同一片连续风场。
- 小尺度按实体与骨骼哈希去相关：每个模型、每根骨骼有各自的涡旋相位、幅度调制与气动迟滞，不创建随机对象、不依赖墙钟，重复渲染可复现。
- 风强综合维度基础值、雨量雷暴、相对海平面高度、浸水与开阔度探测；室内与水下仅保留很弱的气流。
- 风是加在弹簧上的侧向偏置并扣除持续分量，只保留阵风，露天站立不会常年斜着一片裙摆。

### 模型渲染修正

- 按实际顶点为每个 cube 独立重算六面外法线与外向绕序，修正 mirror cube 在使用 `gl_FrontFacing` 的光影下明暗错误。
- 修复本体 Sodium 路径 DOWN 法线分量的写入错误，只让确实需要绕序修正的骨骼退出批量快速路径。
- 法线与绕序位掩码按网格身份弱缓存，热路径零堆分配，F3+T 与自定义模型热加载会自动失效。

### 原版 AI 优化

- 工作时工具耐久过低会自动从背包寻找备用工具替换，防止附魔工具损坏。
- 对本体 `Brain` 的成功可达判断做短期强失效缓存，并消除拾取传感器的 Stream 临时分配；不改变任务优先级、目标顺序与传感器周期。
- 对呼吸、回区、跟随、内置工作、祈求与拾取的移动目标做短期软协调；拾取已经开始后会在限时承诺内避免被普通跟随打断，物品失效或主人超距传送时立即释放。系统不接管 Activity 或第三方任务，检测到未知写入时自动兼容降级。
- 主人静止时，普通步行跟随不会抢占正在执行的内置工作、拾取或偷吃；主人重新移动或距离达到紧急传送阈值时立即恢复原版跟随。
- 主人连续静止 1 秒后，女仆的空闲、工作与战斗活动范围会瞬时扩展，战斗默认可从常见的 8 格提升至 20 格；主人移动 3 tick 后恢复原范围，Home、坐下、睡眠、拴绳和载具状态不扩展，也不会改写存档半径。
- 内置攻击任务会优先响应女仆受击、主人受击与主人正在攻击的目标，并以 10/20 tick 的受限扫描补充主动索敌；不修改伤害、攻击间隔、武器逻辑或第三方任务。
- 女仆在本体凳子、娱乐座位或未被指挥锁定的原版船只上，可因跟随、拾取或战斗需要自主下乘；主人离开普通船只后女仆也会立即下船，不再受本体短暂离船窗口限制。指挥锁定、主人命令坐下和其他模组载具仍受保护，坐式工作也不会被拾取打断。
- 服务端可通过 `tlm_companionship/server.toml` 配置动态半径、战斗扫描和 `OFF / OBSERVE / CONSERVATIVE` 协调模式，并用 `/tlmcompanionship ai stats` 查看性能、范围、索敌与协调指标。

### 数据驱动意图 AI

- 好感度等级达到 1 后，主人在跟随模式下用准星连续注视自己的女仆 0.1 秒，可让空闲的她走到主人身边；抵达后进入 3 秒指挥窗口，期间持续跟随主人，并会尝试与主人共乘有空位的实体。主人所坐实体满员时，她会寻找 3 格内同类型且能接纳玩家的空位，TLM 凳子与娱乐座可跨类型互通；主人刚离座时则接替其释放的位置。
- 指挥窗口选中的座位会保持锁定，不会被普通跟随、拾取、日程或载具联动自动解除；非 Home 模式下，锁定的 TLM 凳子或娱乐座位仍允许在主人达到紧急传送距离时解除并传送，有效战斗危险和主人空手右键下座也可立即释放。注视手势允许隔着方块生效，但不会打断战斗、回区、呼吸、拾取、偷吃、工作目标或正在使用的物品。
- 饥饿值不高于 40、手中和背包都没有合法食物时，女仆会优先前往 8 格内存有合法食物的 TLM 零食柜，到达后只取一份并立即进食；战斗、硬移动、命令坐下和指挥座位不会被抢占，Home 模式仍可使用家中的零食柜。
- 自动进食失败并出现“需要食物”提示时会提交一次确定性的求食信号；普通低饥饿分支默认每 5 秒有 10% 概率激活，饥饿值 20 及以下且好感度高于 2 级时概率提升至 25%。三条分支只保留触发条件和优先级差异，统一复用“靠近主人后面向主人做请求动作”的 Data Pack 计划；战斗、Home 和主人命令坐下等硬状态不会被抢占。
- 内置工作目标序列结束且 1 秒内没有新目标时，女仆会执行一次归队；新一轮随机游走默认有 10% 概率改为走回主人身边。连续工作只在整轮结束后触发，战斗、拾取、回区、呼吸、第三方任务和硬移动状态均会优先。
- 七个内置意图由服务端 Data Pack 中的 `maid_ai/intents/*.json` 与 `maid_ai/plans/*.json` 定义，通过 Utility 评分和小型状态机统一调度；`/reload` 会原子切换已校验目录，无效上层资源回退到下层有效定义，整批失败则保留上一代。
- 零食柜、主人和可坐实体进入事件驱动的 Affordance 索引；查询只粗筛已加载 top-K 候选。容器槽、座位、放置点和共享请求使用带 fencing token 的 Claim，取消、死亡、卸载、超时和 reload 都会释放。
- 计划可在战斗打断后按策略重启步骤、恢复检查点或重规划后缀；执行终态以去重 Outcome 记录。短期事件和 trace 有界保存在内存，高价值记忆才随女仆持久化。
- `maid_ai/abilities/*.json` 可把受支持的高层模板编译为同一套 Intent/Plan。首个能力 `deploy_boat` 会优先复用空船，否则安全 Claim 水面并在生成成功后才扣物；同一主人下多名女仆通过公平竞标只选一个自主响应者。
- 有界学习把 Outcome 分别投影为对象可靠性、主人偏好和时段习惯；默认只做影子记录。启用后也只能软修正 Utility，不能绕过安全条件、命令、能力授权或资源容量，并支持查看、冻结、重置和导出。
- `tlm_companionship/behavior-server.toml` 只保留总开关、评估预算、rollout、学习模式、诊断开关以及注视传感器范围/持续时间；饥饿阈值、概率、等待、冷却和计划步骤均以 Data Pack 为唯一来源。
- 管理员可用 `/tlmcompanionship ai stats` 查看目录代际和调度计数，用 `/tlmcompanionship ai explain <女仆>` 查看当前意图、计划状态、候选效用和阻塞原因，并通过 `ai ability` 与 `ai learning` 子命令管理能力和学习。数据格式与扩展方式见 [`docs/architecture/intent-ai-data.md`](docs/architecture/intent-ai-data.md)。

## 依赖与安装

### 环境要求

- **Minecraft**：`1.20.1`
- **Mod Loader**：`Forge 47.4.0` 及以上
- **前置模组**：[Touhou Little Maid](https://github.com/TartaricAcid/TouhouLittleMaid) `>= 1.5.3`（必须）

### 可选兼容

- **Sodium / Embeddium**：已适配其渲染快速路径，法线修正与批量路径共存。
- **光影包**：外法线修正针对使用 `gl_FrontFacing` 的光影场景，阴影阶段不参与面追踪。

### 安装方法

1. 确认已安装对应版本的 Forge 与车万女仆本体。
2. 从 [Releases](https://github.com/Re-Summer75/Touhou-Little-Maid-Companionship/releases) 下载 `tlm-companionship-1.20.1-forge-x.x.x.jar`，放入游戏根目录的 `mods` 文件夹。
3. 启动游戏即可。

> 当前处于 `v0.1.0` 测试阶段，功能可用但仍在快速迭代，建议先备份存档。


## 参与贡献

欢迎提交 Bug 报告、兼容性问题、功能建议与 Pull Request。自定义模型在骨骼物理下表现异常时，请附上模型文件与调试棒的转储信息。

### 需要先知道的开发方式

本项目全程使用 AI Agent 辅助开发，**单次提交的改动范围通常较大**，可能同时涉及多个模块的重构、文档同步与验证套件更新。这带来两点影响：

- 主分支推进较快，动手前建议先同步最新代码，避免在已被重构掉的结构上做修改。
- 上游历史里的大颗粒提交不代表本仓库的提交规范。**请你的 PR 采用原子化提交**：一个提交只做一件事，便于评审、定位回归与必要时单独回滚。

### 提交建议

- 一个 PR 聚焦一个问题或一个特性，不要把无关的格式化、重命名混进来。
- 提交信息使用 `type(scope): 描述` 形式，例如 `fix(physics): 修正裙摆碰撞代理半径`。
- 改动涉及物理、进度或渲染法线时，请本地跑过 `./gradlew --offline cleanTest check`。
- 新增机制请同步更新 `docs/` 下对应模块的文档。

### 流程

1. Fork 本仓库，从目标版本分支（当前为 `1.20.1`）切出特性分支。
2. 按原子化粒度完成提交。
3. 推送分支并开启 Pull Request，说明改动动机与验证方式。
