# 女仆状态反馈系统

本功能为“TLM：朝夕相伴”提供独立饥饿值、自动进食、低耐久工具替换、状态气泡和短暂请求动作。

## 饥饿规则

| 项目 | 数值 |
| --- | --- |
| 初始与最大饥饿值 | 100 |
| 初始饱和度 | 25 |
| 饱和度上限 | 不超过当前饥饿值，最高 100 |
| 自动进食阈值 | 40 |
| 工作消耗 | 每 200 tick 降 1 |
| 空闲消耗 | 每 400 tick 降 1 |
| 休息或睡眠 | 不消耗 |
| 食物恢复 | 原版营养值 × 5 |
| 饱和度恢复 | 原版营养值 × 饱和系数 × 2 × 5 |

饥饿只在女仆实体实际加载期间计算，不会在区块卸载后继续下降。活动消耗会优先扣除饱和度，饱和度耗尽后才降低饥饿值。

当饱和度达到最高值 `100` 时，玩家不能继续喂食女仆；服务端会拒绝普通食物、金苹果和整块蛋糕等所有口部喂食，并触发拒绝反馈。只有饱和度因活动或回血消耗而低于 `100` 后才能再次喂食。

当饥饿值不高于 40 时，女仆会：

1. 检查当前手中的食物。
2. 检查可用背包中的食物。
3. 复用车万女仆 Work Meal 的食物处理器和黑名单。
4. 找到食物时自动进食。
5. 没有食物时显示“我需要食物……”。

本体 Work、Heal 和 Home Meal 产生的正常进食也会恢复附属饥饿值。
玩家直接喂食蛋糕时会消耗一整个蛋糕，并按原版 7 片蛋糕合计的营养值 `14` 和饱和系数 `0.1` 计算恢复；创造模式不消耗蛋糕。

饥饿值不会造成扣血、减速或强制停工。

## 饥饿值回血

女仆受伤时使用两套彼此独立的回血计时器；进食和使用物品期间也会同步执行。基础饥饿值回血保持原有三档速度：

| 饥饿值 | 恢复速度 |
| --- | --- |
| `80–100` | 每 10 tick 恢复 1 点生命 |
| `60–79` | 每 80 tick 恢复 1 点生命 |
| `41–59` | 每 160 tick 恢复 1 点生命 |
| `0–40` | 停止额外回血，保留饥饿值用于自动进食 |

饥饿值高于 40 且仍有饱和度时，第二套计时器会每 `10 tick` 额外执行一次快速饱和回血。它不会替代、暂停或重置基础饥饿值回血；两套计时器同一 tick 到期时会依次恢复生命，直到达到生命上限。

快速饱和回血按玩家公式计算：每次最多使用相当于原版 `6` 点的饱和度产生回血，并增加同量消耗度；消耗度超过 `4` 时扣除相当于玩家 `1` 点、即本系统 `5` 点饱和度。饱和度不足时单次回血量会按比例降低。基础饥饿值回血仍在每次成功恢复 1 点生命后消耗 1 点饥饿值。

满血或饥饿值不高于 40 时会重置回血计时；进食不会暂停或清零计时。本体随机回血和治疗食物逻辑仍然保留，并可与饥饿值回血同步生效。界面中的饥饿值条复用本体经验条的高光和阴影纹理并着色为橙色，底部用同纹理的亮黄色细层显示当前饱和度；悬浮提示同时列出两项数值。

本体的 `randomRestoreHealth()` 原本会在客户端和服务端分别随机执行，可能造成客户端先显示恢复 1 点生命、随后又被服务端真实生命值覆盖。附属只阻止客户端执行该随机回血，服务端原有随机回血仍然保留。

## 工具规则

检查范围：

- 主手
- 副手
- 不检查护甲和饰品

警戒线：

```text
剩余耐久 ≤ max(10, 最大耐久的 10%)
```

进入警戒线后：

1. 扫描女仆可用背包。
2. 只查找相同物品 ID 的备用工具。
3. 候选工具必须高于耐久警戒线。
4. 多个候选中选择剩余耐久最高的一个。
5. 新工具放入原手，旧工具放回候选所在槽位。

没有备用工具时，女仆继续当前工作，但会显示包含剩余耐久比例的进度气泡。

正在使用物品时不会交换工具，以免打断弓、食物等使用流程。

## 气泡规则

| 项目 | 行为 |
| --- | --- |
| 状态优先级 | -1 |
| 显示时间 | 15 秒 |
| 重复冷却 | 60 秒 |
| AI waiting 存在时 | 状态气泡让路 |
| 删除规则 | 只删除本功能记录的气泡 key |

低优先级保证状态提示不会在气泡槽已满时挤掉 AI 等待或回复。

状态类型：

- 缺食物：文本气泡。
- 工具低耐久：进度气泡。
- 自动更换成功：文本确认气泡。

## 动作规则

缺食物或工具没有备用时，如果主人在 8 格内：

1. 女仆停止当前导航。
2. 看向主人。
3. 进入祈求动作 60 tick。
4. 时间结束、主人离开、女仆睡眠或死亡时恢复。

女仆不会主动走向主人。

自动更换工具成功时只挥动对应手，不进入祈求状态。

如果缺食物和工具告警同时发生，工具告警拥有更高的动作优先级。

## 数据与同步

- 饥饿值、饱和度和消耗度存入 TLM `TaskDataKey`，随女仆 NBT 保存并同步。
- 旧 `maid_intelligence:status_state` 会在读取时迁移到 `tlm_companionship:status_state`，避免 MOD ID 更名造成状态清零。
- 旧存档只有饥饿值字段时，饱和度和消耗度默认按 `0` 读取。
- 气泡、冷却、待恢复营养值和动作计时只保存在服务端运行时。
- 气泡通过 TLM `ChatBubbleManager` 自动同步。
- 祈求动作通过 TLM `DATA_BEGGING` 自动同步。
- 本功能不新增网络包。
- 本功能不使用 TLM 当前未参与业务的 `EntityMaid.getHunger()`。
