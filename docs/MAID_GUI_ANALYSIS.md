# 车万女仆界面分析手册

本文档用于帮助“TLM：朝夕相伴”开发者快速看懂车万女仆界面的布局，判断某块区域由什么代码负责，以及为新功能寻找不会冲突的位置。

## 1. 分析基准

- Minecraft：1.20.1
- Forge：47.4.0
- 车万女仆：1.5.3 Forge
- 本体源码分支：`1.20`
- 本体源码提交：`8a3ac5e`
- 本体源码位置：`_reference/TouhouLittleMaid`
- 核心界面类：
  `_reference/TouhouLittleMaid/src/main/java/com/github/tartaricacid/touhoulittlemaid/client/gui/entity/maid/AbstractMaidContainerGui.java`

后续升级车万女仆版本时，应重新核对本文档中的坐标和事件顺序。

## 2. 先理解坐标

女仆主界面的基础大小是 `256×256`。

界面左上角在代码中叫：

- `leftPos`：界面左边相对于游戏窗口的位置
- `topPos`：界面顶部相对于游戏窗口的位置

本文档中的所有坐标均为“界面相对坐标”。

例如，详情按钮的位置是 `(8, 14)`，它真正显示在屏幕上的位置为：

```text
屏幕 X = leftPos + 8
屏幕 Y = topPos + 14
```

因此，附属模组不能直接使用固定的屏幕像素坐标，否则玩家改变窗口大小或 GUI 缩放后，控件就会偏移。

正确写法始终应以 `leftPos`、`topPos` 为基准。

## 3. 整体布局

可以把女仆界面理解为三部分：

```text
              左侧任务列表                   主界面 256×256                  右侧栏

      x=-93                         x=0                               x=251
        ┌────────────────┐            ┌───────────────────────────────┐ ┌──────┐
        │ 翻页 / 关闭     │            │ 详情    声音/皮肤   顶部 Tab  │ │ 手册 │
        │                │            │                               │ ├──────┤
        │ 每页 12 个任务  │            │ 女仆模型      装备/背包/配置区 │ │ 配置 │
        │                │            │                               │ └──────┘
        │                │            │ HP / 护甲 / 经验 / 饱食       │
        │                │            │ 当前任务                      │
        │                │            │ 日程                          │
        │                │            │ 归家 / 拾取 / 骑乘            │
        │                │            │ 模型下载      玩家背包         │
        └────────────────┘            └───────────────────────────────┘
```

左侧任务列表只有在玩家点击当前任务区域后才会展开。

右侧栏位于主界面范围之外，当前用于任务手册和全局配置，也可能被本体未来版本继续扩展。

## 5. 顶部按钮

### 5.1 女仆详情按钮

- 坐标：`(8, 14)`
- 大小：`9×9`
- 点击：无操作
- 悬停：显示女仆详细信息

原生详情内容依次包括：

1. 标题
2. 主人（存在主人时）
3. 女仆模型名称
4. 车万女仆本体经验
5. 好感度
6. 五子棋记录

“TLM：朝夕相伴”会在标题之后、其它属性之前插入：

1. 带绿色方块的等级
2. 带绿色方块的升级经验

因此玩家实际看到的顺序是：标题、等级、升级经验，然后才是本体原有属性。

### 5.2 声音与皮肤按钮

| 按钮 | 坐标 | 大小 | 条件 |
| --- | --- | --- | --- |
| 皮肤 | `(62,14)` | `9×9` | 始终 |
| 声音 | `(52,14)` | `9×9` | 未安装 YSM |
| 声音 | `(42,14)` | `9×9` | 安装 YSM |
| YSM 皮肤 | `(52,14)` | `9×9` | 安装 YSM |

这意味着 `(42,14)` 到 `(70,22)` 之间的按钮会根据其他模组是否安装而改变，附属模组不能把新按钮直接放进这个范围。

### 5.3 顶部 Tab

| Tab | 坐标 | 大小 |
| --- | --- | --- |
| 主界面 | `(94,5)` | `24×26` |
| 任务配置 | `(119,5)` | `24×26` |
| 女仆配置 | `(144,5)` | `24×26` |

顶部 Tab 会切换到不同容器界面，但所有界面仍继承 `AbstractMaidContainerGui`，所以左侧的女仆状态区通常保持不变。

## 6. 左侧状态与控制区域

### 6.1 四条状态条

| 状态 | 条形坐标 | 图标坐标 | 数字坐标 | 数据含义 |
| --- | --- | --- | --- | --- |
| HP | `(5,113)` | `(53,113)` | `(63,114)` | 当前生命值 |
| 护甲 | `(5,124)` | `(53,124)` | `(63,125)` | 当前护甲值 |
| 本体经验 | `(5,135)` | `(53,135)` | `(63,136)` | 车万女仆自己的经验 |
| 饱食度 | `(5,146)` | `(53,146)` | `(63,147)` | 附属饱食度 `0–100`；使用原版鸡腿图标；复用本体经验条的高光阴影纹理并着橙色，底部黄色纹理层显示饱和度 |

需要特别注意：

> TLM 本体经验和“TLM：朝夕相伴”的等级经验是两套完全独立的数据。

本体好感度数据及其饰品栏解锁逻辑仍然保留，只是不再占用左侧第四条状态栏；详情悬浮框仍可查看好感度。

如果以后把附属等级直接画在状态条附近，必须使用不同图标或明确文字，避免玩家误以为两种经验是同一个系统。

### 6.2 当前任务

- 点击区域：`(4,159,71,21)`
- 任务图标：`(6,161)`
- 任务名称：`(28,165)`

点击后会展开左侧任务列表，同时重新执行界面初始化。

因此，通过 `MaidContainerGuiEvent.Init` 添加的自定义按钮，必须在每次初始化时重新注册。

### 6.3 日程

- 区域背景：`(6,178,67,25)`
- 按钮：`(9,187,61,13)`

点击会循环切换女仆日程，悬停会显示当前时间和活动安排。

### 6.4 底部状态按钮

| 按钮 | 坐标 | 大小 |
| --- | --- | --- |
| 归家模式 | `(9,206)` | `20×20` |
| 自动拾取 | `(30,206)` | `20×20` |
| 允许骑乘 | `(51,206)` | `20×20` |
| 模型下载 | `(20,230)` | `41×20` |

模型下载按钮还会绘制一个高层级气泡，所以它附近不适合放置需要悬停显示的附属控件。

## 9. 左侧任务列表

展开后的任务面板范围为：

```text
x = -93
y = 5
宽 = 92
高 = 251
```

任务控制按钮：

| 控件 | 坐标 | 大小 |
| --- | --- | --- |
| 上一页 | `(-89,9)` | `16×13` |
| 下一页 | `(-72,9)` | `16×13` |
| 关闭 | `(-19,9)` | `13×13` |
| 任务项 | `(-89,23+19×序号)` | `83×19` |

每页最多显示 12 个任务。

任务列表范围内的鼠标滚轮会被本体接管，用于翻页。

因此：

- 不能在 `x<0` 区域放置常驻附属界面。
- 如果确实需要左侧大面板，必须在任务列表关闭时才显示。
- 显示前必须检测 `isTaskListOpen()`。

## 10. 右侧侧栏

右侧侧栏从 `(251,37)` 开始，已经存在：

| 按钮 | 坐标 | 大小 |
| --- | --- | --- |
| 任务手册 | `(251,37)` | `26×24` |
| 全局配置 | `(251,62)` | `26×24` |

本体向 JEI、REI、EMI 声明的右侧屏蔽区约为：

```text
(251,37,21,99)
```

理论上可以在 `(251,87)` 下方继续添加侧栏按钮，但存在两个问题：

1. 本体未来版本可能继续向下添加官方按钮。
2. 该区域已经被配方查看模组视为界面占用区。

所以右侧栏适合较大的独立功能入口，但不适合未经检测就硬编码。

## 11. 界面渲染顺序

了解渲染顺序可以解释“为什么某段文字被按钮或 Tooltip 遮住”。

从低到高大致为：

1. `drawModInfo`
2. `super.render`
3. `renderBg`
4. 主背景与模型
5. 状态条与任务面板
6. 原生 Widget
7. 药水效果与当前任务文字
8. `renderAddition`
9. `MaidContainerGuiEvent.Render`
10. 原生 `renderTooltip`
11. `MaidContainerGuiEvent.Tooltip`

其中：

- `Render` 事件适合绘制普通文字、图标和进度条。
- `Tooltip` 事件位于整帧最后，适合绘制悬停提示。
- 通过 `Init` 添加的 Widget 会由本体自动渲染和处理点击。

## 12. 原生 Tooltip 顺序

`AbstractMaidContainerGui.renderTooltip` 的处理顺序为：

1. 物品槽 Tooltip
2. 归家、拾取、骑乘等状态按钮
3. 皮肤、声音、任务控制等按钮
4. 子界面附加 Tooltip
5. 女仆详情 Tooltip
6. 日程 Tooltip
7. 实现 `ITooltipButton` 的控件
8. 模型下载气泡
9. `MaidContainerGuiEvent.Tooltip`

同一帧中如果多个提示被绘制，后绘制的提示可能覆盖前面的提示。

## 13. 官方提供的附属扩展事件

车万女仆 1.5.3 提供三个主要 GUI 事件。

### 13.1 `MaidContainerGuiEvent.Init`

发布时间：

```text
基础数据初始化
→ 子界面数据初始化
→ 原生按钮初始化
→ 子界面按钮初始化
→ 发布 Init 事件
→ 添加事件注册的按钮
```

适合：

- 添加可点击按钮
- 添加输入控件
- 添加拥有独立命中区的 Widget

注意：

- 按钮 ID 必须唯一。
- 重名时 `addButton` 会静默忽略新按钮。
- 界面重新 `init()` 后需要重新注册。
- 建议使用完整命名空间，例如 `tlm_companionship:level_button`。

### 13.2 `MaidContainerGuiEvent.Render`

在原生按钮绘制完成后、原生 Tooltip 之前触发。

适合：

- 绘制等级数字
- 绘制额外图标
- 绘制附属进度条
- 绘制不需要点击的状态信息

该事件不会自动处理鼠标输入。

### 13.3 `MaidContainerGuiEvent.Tooltip`

在原生 Tooltip 完成后触发，是整个女仆界面渲染流程的最后阶段。

适合：

- 为附属按钮绘制提示
- 绘制需要覆盖在最上层的文字

它不能直接修改本体已经构造好的详情列表。

### 13.4 `RenderTooltipEvent.GatherComponents`

这是 Forge 通用事件，不是车万女仆专属事件。

它允许在 Tooltip 真正绘制前修改提示组件列表。

“TLM：朝夕相伴”当前正是通过它，把等级信息加入本体详情 Tooltip。

优点：

- 不占用界面空间。
- 可以直接成为本体详情的一部分。
- 所有继承 `AbstractMaidContainerGui` 的界面都能使用。

缺点：

- 它是全局事件，必须精确判断当前 Tooltip 是否属于女仆详情。
- 本体更改翻译键或 Tooltip 构造方式后，现有匹配可能失效。
- 其他附属也修改同一个 Tooltip 时，最终顺序取决于事件处理顺序。

## 14. 当前等级信息的位置

当前实现文件：

```text
src/main/java/com/laixia/maidintelligence/feature/level/client/LevelGuiHandler.java
```

当前流程：

```text
玩家悬停详情按钮
→ 本体 renderMaidInfo 构造详情列表
→ Forge 发布 GatherComponents
→ LevelGuiHandler 判断是否为女仆详情
→ 读取当前女仆等级
→ 在标题后插入“█ 等级”
→ 紧接着插入“█ 升级经验”
```

当前最终顺序为：

```text
女仆详细
█ 等级
█ 升级经验
主人
模型名
本体经验
好感度
五子棋
```

绿色方块与本体属性行保持相同的视觉结构，等级信息位于最容易看到的位置。

## 15. 推荐的新功能位置

### 15.1 推荐 A：继续使用详情 Tooltip

位置：

```text
原生详情按钮 (8,14,9,9)
```

适合：

- 等级
- 当前经验
- 升级所需经验
- 属性说明

优点：

- 不占用界面空间。
- 与“女仆详细”的概念一致。
- 不会遮挡背包和模型。

当前等级功能应继续使用这个位置，但建议改进目标识别和行插入顺序。

### 15.2 推荐 B：新增顶部小按钮

推荐坐标：

```text
(72,14,9,9)
```

该位置位于皮肤按钮右侧、顶部 Tab 左侧。

适合：

- 独立等级图标
- 打开等级详情页
- 显示独立等级 Tooltip

风险：

- 本体未来可能增加新的顶部按钮。
- 每次升级本体后都要重新确认。

### 15.3 可选 C：详情按钮右侧

推荐坐标：

```text
(18,14,9,9)
```

适合添加第二个信息类按钮，但视觉上可能与原生详情按钮重复。

### 15.4 可选 D：状态条右侧窄区

大致区域：

```text
(73,113) 到 (84,155)
```

这里只适合：

- 很窄的竖向进度条

### 15.5 谨慎使用：右侧侧栏

## 17. 风险清单

| 风险 | 当前情况 | 建议 |
| --- | --- | --- |
| 详情识别依赖翻译文本 | 使用 `contains` 判断本地化后的标题 | 改为更严格的首行或组件结构判断 |
| 两套经验容易混淆 | 都使用“经验”概念 | 文案明确区分“本体经验”和“等级经验” |
| 按钮重名 | `addButton` 静默拒绝 | 始终使用带命名空间的 ID |
| 左侧任务列表是静态状态 | 不同女仆界面共享开关状态 | 不在 `x<0` 放置常驻内容 |
| 右侧栏可能扩展 | 本体已有两个 SideTab | 添加前检查已有按钮和可用空间 |
| 兼容模组改变布局 | YSM、Curios、IPN 会增加控件 | 测试常见兼容模组组合 |

## 18. 开发检查清单

添加任何新 GUI 功能前，请确认：

- [ ] 坐标使用 `leftPos` 和 `topPos`。
- [ ] 没有覆盖女仆背包、玩家背包或状态按钮。
- [ ] 测试任务列表展开和关闭两种状态。

## 20. 当前结论

女仆主界面并没有足够大的固定空白区域来直接显示两行等级文字。

现阶段最合理的方案是：

1. 等级和升级经验继续显示在原生“女仆详细”Tooltip 中。
2. 在标题之后优先显示等级信息，并使用与本体一致的绿色方块前缀。
3. 明确区分本体经验与等级经验。
4. 将来如果需要独立等级界面，在 `(72,14,9,9)` 添加小图标按钮。
5. 所有进一步 GUI 开发都以本文件的坐标表为基准。
