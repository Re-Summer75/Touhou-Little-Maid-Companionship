# 测试章程：分层、快照、影响面

这份章程起因于一次自我检讨——玩家的原话是"你不觉得从开始到现在，你的测试写的方式
很有问题吗，一直在返工"。

返工是事实。仅最近一轮，测试与基准就返工四次：取证逐层加（为定位一个 bug 跑了五
轮）、基准采样换了三种方法、两次低级编译错误、一次度量选错。**其中只有一次是"想错
了"，其余三次都是"反馈太慢导致想当然"**——每验证一个假设要等十七分钟，人就不再"先
想清楚再验证"，而是"先跑跑看"。

## 0. 数据

| | 数量 |
|---|---|
| GameTest 总数 | 498 |
| 其中寻路相关（stepisland 83、pathing 63、liddedtee 54、fencepen 22、invertedtee 16、penroute 8） | **246，占一半** |
| 纯 JVM 单元测试 | **2** |
| 全量一轮 | 17–20 分钟 |

**几乎所有验证都要起一个 Minecraft 服务器、造世界、跑 tick。** 这既是十七分钟的来
源，也是返工的来源。

## 1. 五层

| 层 | 内容 | 目标 | 何时跑 |
|---|---|---|---|
| **L0 纯 JVM** | 弹道数学、定价、几何判据、纯函数 | < 1 秒 | 每次改动 |
| **L1 快照** | 地形 → 路径形状（锚点＋动作序列） | 秒级 | 改寻路必跑 |
| **L2 影响面** | 按改动路径映射到 batch | 1–3 分钟 | 日常验证 |
| **L3 全量** | 全部 GameTest | ~17 分钟 | **提交前** |
| **L4 基准** | 性能读数 | 按需 | 性能工作时 |

原则：**能在上一层验证的，不要放到下一层**。一条判据若是纯函数（`launchSpeed`、
`rimDist`、`laneFor` 的几何部分），它就该有 L0 测试；起服务器去验一个纯函数，是
把十七分钟花在本该一毫秒的事情上。

## 2. 快照测试

寻路的多数问题是"**路的形状不对**"，而不是"她摔了"。形状可以脱离游戏来验：

- **输入**：地形字符矩阵 ＋ 起点 ＋ 终点
- **输出**：锚点序列、动作序列（WALK/LEAP/CLIMB/DROP）、是否到达、站数
- **对比**：与录制的快照 diff

`VoxelAstar` 只依赖 `BlockGetter`，给一个内存实现就能在纯 JVM 里跑——不必起服务器。

**产出是 diff 而不是红绿**：路径变了就把新旧摆出来，由人判断是改进还是回归。举一
个现成的例子：基准发现"空地无障碍 32 格铺成 17 站，本该 2 站"（任意角拉直没吃
满），这种问题快照一眼可见，而现在要靠基准的站数字段间接发现。

## 3. 影响面映射

改动路径 → 该跑的 batch：

| 改了什么 | 跑什么 |
|---|---|
| `pathing/**` | pathing, stepisland, liddedtee, fencepen, invertedtee, penroute |
| `combat/**` | combat*, dojo* |
| `errand/**` | pickupreach, loosefood |
| `disposition/`、`status/`、`interaction/` | 各自的 batch |
| `kernel/`、`shared/` | 全量（底座动了谁都可能受影响） |

## 4. 六条规矩

**一、取证一次加够。** 这次为定位一个 bug 加了五轮读数（起跳窗口 → 竖直速度 → 差
事返回值 → 目标可收性 → 物品存活），每轮十七分钟。设计取证时先把**所有候选分支列
出来**，一次记全——多记几个字段几乎不要钱，多跑一轮要十七分钟。

**二、能自相矛盾的读数，比没有读数更危险。** 基准曾报出同一条链 339ms 与 21ms、
一只女仆 455ms，而我差点据此下结论。**读数必须能自证**：p50/p95/mean 互相自洽、
同一量的不同档位有单调关系。矛盾说明测量方法错了，不是"数据有噪声"。

**三、测量的边界要划在被测对象上。** 三次失败的量法都栽在这里：
`getAverageTickTime` 是全服百 tick 滑动平均（掺进上一局的负载）；tick 间隔量的是
整台服务器多忙（掺进框架开销与 GC）；`PathClock` 是全局静态（掺进同 JVM 里别的女
仆——对照组根本不走自有引擎，却记到了 19 次规划）。**量自己的代码，且只量这一
局。**

**四、没见过红的测试不算测试。** 新钉子要先确认它在预期的破坏下真的会红，否则可能
只是在测"程序没崩"。

**五、失败信息要能定位。** "她没跳"这样的断言让一个场景连红四十轮；改成打印"起跳
窗口开了几 tick、竖直速度峰值、差事返回值"之后，两轮就查到了根因（而且根因是测试
自己的前提错了）。

**六、截断的轮次不作数。** 没有 `N GAME TESTS COMPLETE` 横幅的轮次，红数是假的——
被停摆或硬顶截断的轮次会报出漂亮的低红数。台账工具已按此判定。
