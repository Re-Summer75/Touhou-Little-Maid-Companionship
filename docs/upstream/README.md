# 上游 TouhouLittleMaid 机制参考

本目录记录**本体已经实现了什么**，用途只有一个：不要再重写上游已有的东西，也不要再对上游的数值想当然。

写它的直接原因是两次真实代价：

- 我们判定"零伤害做不到"的整个论证，建立在"女仆和僵尸攻击距离相同"这个前提上。**错的**——本体覆写了 `getMeleeAttackRangeSqr`，女仆的触及是属性加好感度加成，零级就比僵尸远，满好感远出五格。基于错前提做的一串取舍全部作废。
- 我们按原版几何硬写了一套横扫盒子。本体自己有 `FavorabilityManager.getSweepRange`，范围随好感度分四档放大。我们的实现在高好感下比本体设计的窄。

两次都不是"想法错了"，是**没查**。

## 怎么用：知道本体有什么，不等于要照着做

**自由模式脱离本体，是近乎独立的存在。** 本体的行为、决策与机制实现一概不用，也不必与
本体的数值保持一致——它有自己的一套。查这些文档是为了**不漏世界的事实、不重复造轮子造
错**，不是为了对齐本体。

要读的只有世界的事实：属性、好感度点数、饥饿、物品、实体几何。玩家的装备与养成必须算数，
所以这些一律读实时值，不写死常量。

其它工作模式是另一回事：那里保持本体原样，我们只是旁观者，用本体的事件即可。

### 检查清单

- 任何"她能做到多远/多快/多疼"的数字 → 看 [attributes.md](attributes.md)，确认是不是属性、是不是被好感度改过。**读值，不要写死。**
- 任何"我们需要一个新的行为钩子" → **自由模式先问这件事是不是本来就该我们自己实现**；其它模式看 [tasks-and-brain.md](tasks-and-brain.md) 与 [events-and-baubles.md](events-and-baubles.md)。

## 维护

上游版本升级后这些数值可能变。每篇都标了源文件路径与行号范围，核对时直接对照 `_reference/TouhouLittleMaid/`。**行号会漂，类名和常量名不会**——优先按名字找。

本目录只描述上游。我们自己的行为写在 [docs/maid-behaviors/](../maid-behaviors/)。
