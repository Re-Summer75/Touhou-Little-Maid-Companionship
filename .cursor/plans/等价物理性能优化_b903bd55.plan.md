# 等价物理解算性能优化

## 1. 建立严格等价基线
- 扩展 [`src/test/java/com/laixia/maidintelligence/feature/physics/client/BonePhysicsVerification.java`](src/test/java/com/laixia/maidintelligence/feature/physics/client/BonePhysicsVerification.java)，固定 `winefox` 与匿名模型的 dt、移动、转身、暂停和 pivot 补偿序列，记录优化前后骨骼 rotation/position 与弹簧方向，容差控制在 `1e-5`。
- 新增独立性能基准入口，只报告预热后的每帧耗时、访问节点数和线程分配量，不把易波动的绝对时间作为 `check` 门禁。

## 2. 复用共享模型发现结果
- 在 [`PhysicsBonePlanCache.java`](src/main/java/com/laixia/maidintelligence/feature/physics/client/PhysicsBonePlanCache.java) 上增加 `GeoModel` 级弱引用模板缓存；模板按 `modelId` 分区，并在现有资源/sidecar 重载路径中同步清空。
- 模板用共享 `GeoBone` 身份保存不可变 `Decision`、路径和静态运动学数据；每个 `AnimatedGeoModel` 仅执行 O(N) live bone 绑定，仍生成实例隔离的 [`PhysicsBoneSelectionPlan.java`](src/main/java/com/laixia/maidintelligence/feature/physics/client/PhysicsBoneSelectionPlan.java)，避免跨实体骨骼引用泄漏。

## 3. 构建最小活动骨架
- 新增 `client/solver/PhysicsSolverLayout.java`：对完整骨架构建“所有 driven 骨骼到根路径的并集”，即最小活动 Steiner 子树。
- 扁平预序节点保存 live bone、父活动索引、角色（祖先/驱动）、driven slot 与预计算 [`BoneKinematics`](src/main/java/com/laixia/maidintelligence/feature/physics/client/solver/BoneKinematics.java) 常量；无受驱动后代的整棵分支严格跳过。
- 保持当前关键语义：祖先使用动画姿态传播，驱动骨先按动画姿态积分，再把施加后的朝向传给子骨。

## 4. 改写为零分配迭代热路径
- 将 [`MaidBonePhysics.java`](src/main/java/com/laixia/maidintelligence/feature/physics/client/MaidBonePhysics.java) 的全树递归和 IdentityHashMap 热查询拆到新的 `client/solver/SpringBoneSolver.java`，按 layout 直接索引迭代。
- 为每个活动节点持久复用 rendered quaternion；每实体复用其余 Quaternionf/Vector3f scratch，改用 out 参数运算，消除每帧 `new Quaternionf`、`new Vector3f`、`MotionSignals` 与每骨 force 对象。
- 为 [`AdaptiveMotionFilter.java`](src/main/java/com/laixia/maidintelligence/feature/physics/client/solver/AdaptiveMotionFilter.java)、[`MotionNoiseGate.java`](src/main/java/com/laixia/maidintelligence/feature/physics/client/solver/MotionNoiseGate.java)、[`MotionSignalSampler.java`](src/main/java/com/laixia/maidintelligence/feature/physics/client/solver/MotionSignalSampler.java) 和 pivot 补偿增加 `updateInto`/`...Into` API，保留现有滤波公式和 reset 行为。

## 5. 生命周期、验证与文档
- 模型切换、实体遗忘、F3+T 和 TLM 热加载时同时失效 layout、runtime 与 GeoModel 模板；不修改现有 24 格门控及超距清状态行为。
- 验证模板绑定与完整 discovery 的 driven path 完全一致；验证活动布局只包含 driven 骨和祖先；逐帧比较旧/新解算输出。
- 运行 `./gradlew.bat --offline cleanTest check`、性能基准和 lint，并更新 [`docs/physics/README.md`](docs/physics/README.md) 记录活动骨架、模板缓存、零分配热路径及基准方法。

明确排除：降频、距离 LOD、视锥/遮挡跳过、异步首帧 discovery；这些都会改变当前效果或状态连续性。
